# موتور و محتوای مستقل

`web/engine.js` موتور خالص JavaScript است؛ به DOM، شبکه یا وردپرس وابسته نیست. همهٔ شروط با داده بررسی می‌شوند و هیچ متن یا عبارت شرطی از JSON با eval اجرا نمی‌شود.

`web/cases/case47.json` شامل معرفی، صحنه‌ها/نقاط قابل لمس، شخصیت‌ها، پرسش‌ها، جوایز مدرکی، تناقض‌ها، استنتاج‌ها/راهنما، خط زمانی و پایان‌هاست. `tools/author_case.py` نسخهٔ قابل‌ویرایش نویسنده را به JSON تبدیل می‌کند. اگر JSON را مستقیم ویرایش می‌کنید، اجرای دوبارهٔ author_case آن را بازنویسی خواهد کرد؛ build_web فقط JSON را می‌خواند.

`web/investigator.json` هویت، معرفی و نقل‌قول کارآگاه را جدا از داستان پرونده نگه می‌دارد. تصویر او `web/assets/investigator.png` است. نام مجموعه همچنان انتخاب نشده است. وضعیت فهرست از ذخیرهٔ مستقل هر پرونده خوانده می‌شود: شروع‌نشده، در حال بررسی و حل‌شده با پایان درست.

`web/cases/catalog.json` فهرست پرونده‌های بسته است. `tools/build_web.py` JSONها را به `cases.bundle.js` تبدیل می‌کند. این تصمیم عمدی است: بازی هنگام اجرا fetch نمی‌کند، ماژول ES از file:// وارد نمی‌کند و به CDN وابسته نیست. ترتیب بارگذاری: boot → data → engine → entitlements → audio → UI. فایل boot و پوستهٔ اندروید پیام خطای خوانا می‌دهند تا شکست بارگذاری به صفحهٔ سفید بی‌توضیح تبدیل نشود.

`web/app.js` رابط مشترک صفحه‌هاست. انتخاب پرونده، مدرک، پرسش، ترکیب مدارک و گزارش به موتور می‌روند. متن‌های مشترک رابط فارسی در app و متن‌های داستانی در پرونده هستند. پوست بصری فعلی و شیت ۱۶ تصویر مدرک برای پرونده ۴۷ طراحی شده؛ برای پرونده‌های جدید می‌توان تصویر و کلاس صحنهٔ تازه در CSS افزود، بدون تغییر منطق موتور.

## قرارداد دادهٔ نسخهٔ ۱

- `evidence`: id/title/kind/summary/body/source.
- `characters[].questions`: id/label/answer/requires/grants.
- `scenes[].hotspots`: evidence/label/x/y؛ مختصات درصدی تصویر.
- `contradictions`: character/claim/proof/requires/response/grants.
- `deductions`: prompt/proof/requires/result/hints.
- `hypotheses`: id/title/prompt/requires/options/answer/proof/result. هر فرضیه یک برداشت و مجموعهٔ مدرک پشتیبان دارد؛ انتخاب اشتباه پیشرفت را تغییر نمی‌دهد.
- `timeline`: requires/slots/events.
- `report`: requires/motives/methods/solution/reviewHints/success/failure. `reviewHints` برای چهار بخش حضور متهم، انگیزه، روش و مدارک، بازخورد غیرمستقیم می‌دهد.

شرط `requires` می‌تواند `evidence`, `questions`, `contradictions`, `deductions`, `hypotheses` (آرایه شناسه‌ها) و `timeline` (بولین) داشته باشد. همهٔ موارد شرط باید برقرار باشند. شناسه‌ها، نسخهٔ schema و ارجاعات هنگام ساخت Engine بررسی می‌شوند. قبل از انتشار پروندهٔ جدید، رسیدن به پایان باید تست شود.

هر معما مجموعهٔ دقیق مدرک می‌خواهد. پاسخ اشتباه هیچ مدرکی را حذف نمی‌کند، منابع مصرف‌شونده وجود ندارد و تمام بازجویی‌ها قابل مرورند. شمار راهنما جدا ثبت می‌شود و دروازهٔ پیشرفت نیست.

## ذخیره

کلید هر پرونده مستقل است: `<caseId>.save.v1`. شامل پیشرفت، پاسخ‌های خط زمانی، راهنما، تنظیمات صدا و پایان است. هر ذخیره checksum و schema دارد؛ ذخیرهٔ قبلی در `:backup` باقی می‌ماند. checksum صرفاً برای تشخیص خرابی است، نه جلوگیری از تقلب. فایل واردشده اعتبارسنجی و با تأیید بازیکن اعمال می‌شود. برای تغییر آیندهٔ ساختار، migrator صریح اضافه و با ذخیرهٔ قدیمی تست شود؛ شناسهٔ مدرک منتشرشده نباید بی‌دلیل تغییر کند.

## افزودن پرونده

۱. JSON جدید با id مستقل و همان قرارداد بسازید.
۲. آن را به catalog.json اضافه کنید.
۳. برای پروندهٔ رایگان entitlement را free بگذارید. برای پروندهٔ پولی permanent و productId مستقل در داده بگذارید.
۴. تصویرها را در assets و پوست اختیاری صحنه‌ها را در CSS اضافه کنید.
۵. آزمون مسیر کامل، ترتیب‌های مختلف کنش‌ها، وارد/صادر کردن و محتوای قفل‌شده را اضافه کنید.
۶. build_web و build_android را اجرا کنید؛ نسخه و versionCode اندروید را افزایش دهید.

در نسخهٔ فعلی بستهٔ پرونده‌ها همراه APK عرضه می‌شود. برای آینده، می‌توان همهٔ محتوا را بسته‌بندی و هر پروندهٔ خریداری‌شده را آفلاین باز کرد. دریافت پرونده از شبکه هنوز پیاده نشده است.

## مالکیت دائمی و کافه‌بازار

`web/entitlements.js` مرز مستقل مالکیت است. نسخهٔ فعلی تنها پروندهٔ رایگان را باز می‌کند. پروندهٔ پولی با یک پرچم در localStorage باز نمی‌شود و خرید آزمایشیِ گمراه‌کننده وجود ندارد.

آداپتور آینده باید `hasVerifiedPermanentOwnership(caseId)`, `purchasePermanent(caseId,productId)` و `restoreVerifiedOwnership()` را پیاده کند. خرید از نوع دائمی/غیرمصرفی خواهد بود. امضا و صحت خرید با SDK و کلید ناشر بررسی، رسید تأییدشده برای اجرای آفلاین نگهداری و حالت لغو، خطا، بازگردانی و تعویض دستگاه تست شود. مجوز اینترنت یا مؤلفهٔ پرداخت قبل از اتصال واقعی افزوده نشود. نمایش UI فروشگاه بعد از تست نسخهٔ اصلی فعال خواهد شد.

## راه‌یابی و یادداشت گفت‌وگو

`Engine.nextLead()` مقصد و متن قدم بعدی را فقط از کارهای بازشده و ثبت‌نشده می‌سازد. این راه‌یابی بخشی از موتور است و روی دادهٔ پرونده کار می‌کند؛ پاسخ معما را فاش نمی‌کند. پاسخ سؤال‌های پرسیده‌شده از دادهٔ پرونده و شناسهٔ سؤال ذخیره‌شده دوباره ساخته می‌شوند، پس قالب ذخیرهٔ قبلی عوض نشده است.

## فرضیه‌های بازیکن

`Engine.judgeHypothesis` انتخاب تفسیر و مجموعهٔ مدرک پشتیبان را جداگانه می‌سنجد. سه فرضیهٔ پروندهٔ ۴۷ پیش از گزارش نهایی لازم‌اند، ولی ترتیب حل آن‌ها آزاد است. ذخیرهٔ نسخه‌های پیشین که کلید `hypotheses` ندارند با آرایهٔ خالی بازیابی می‌شود؛ پایان موفق قدیمی همچنان ۱۰۰٪ است. برای پروندهٔ جدید، فرضیه‌ها و شروطشان را در JSON خودش تعریف و آزمون مسیر کامل اضافه کنید.

`CaseAudio.press` بازخورد کوتاه لمس را در همان AudioContext محلی می‌سازد؛ تنظیم خاموشی، هم این صدا و هم صدای محیط را کنترل می‌کند.

## بازبینی گزارش و انتخاب مدرک

`Engine.report` نخستین بخش ناسازگار پاسخ را با راهنمای داده‌محور `report.reviewHints` مشخص می‌کند. متن بازخورد در ذخیره باقی می‌ماند تا پس از بازکردن دوبارهٔ بازی هم دیده شود؛ ذخیره‌های قدیمی بدون این کلید همچنان خوانده می‌شوند. انتخابگر مدرک در UI بدون دستکاری جواب، جست‌وجو و فیلتر نوع دارد؛ مدارک انتخاب‌شده با پنهان‌کردن فیلتر از بین نمی‌روند.

کنش‌های تحقیق در موتور فقط پس از `Engine.start()` مجازند؛ تنظیمات صدا پیش از شروع هم قابل تغییر است. رابط نیز پیش از شروع، دکمهٔ گزارش را نمایش نمی‌دهد.
